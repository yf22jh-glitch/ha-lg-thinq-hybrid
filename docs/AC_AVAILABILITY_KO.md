# 방별 에어컨 가용성 반복 전환 수정

## 문제와 변경

수집 묶음이 교체될 때 이전 묶음의 `availability=offline`과 다음 묶음의
`online` 사이에 에어컨과 자동 쾌적 설정이 잠깐 비가용으로 표시됐어요.
기기의 인증된 연결 신호와 실행 서비스는 같은 동안 온라인이었어요.

`climate.py`와 `select.py`의 해당 Local 전용 엔티티가 공통 함수
`local_climate_state_available()`로 표시 가능 여부를 확인하도록 바꿨어요.
연결 신호와 상태의 바인딩 세대가 같고, 제공자가 유효하다고 판단한 정확한
불리언 전원 상태가 있을 때 표시해요. 수집 묶음의 완료 표시는 기기 연결
단절로 취급하지 않아요.

실제 기기 연결·실행 서비스·MQTT 연결이 끊기거나 연결 신호가 만료되면
여전히 비가용으로 바뀌어요. 상태나 연결 메시지 삭제, 전원 상태 누락,
바인딩 세대 불일치도 차단해요. 명령 라우터의 기능 권한, 기기 연결,
모드별 입력 검증과 클라우드 대체 금지 조건은 그대로 유지해요.

자동 쾌적 설정은 자동 모드가 아니거나 유효한 선호값이 없으면 계속
값 미확정 상태예요. 이번 수정은 그 값을 만들어 넣지 않아요.

## 검증과 코드 리뷰

- 운영 코드와 원본의 대상 파일 3개가 일치하는 상태에서 수정했어요.
- CST 170·570 모델에서 수정 전 코드의 수집 묶음 교체 비가용을 재현했어요.
- 실제 제공자·라우터와 별도 HA 엔티티를 사용하는 신규 회귀 검사 30개로
  묶음 전환, 실제 단절, 연결 신호 만료, MQTT 메시지 삭제, 세대 변경,
  전원 누락, 권한·기기 연결과 명령 전송 전 검사를 확인했어요.
- 관련 검사 295개 중 294개 통과, 1개는 인접 발행기 저장소 부재로 건너뛰었어요.
- 네 방의 읽기 전용 수집 메시지 32개를 별도 프로세스에서 재생했어요.
  증상 구간에서 기존 두 엔티티는 모두 비가용, 수정본은 모두 가용이었어요.
- 별도 변경분 검토에서 적용을 막는 문제는 발견하지 못했어요. 제공자,
  라우터, MQTT 수신기와 명령 인코더는 변경하지 않았어요.

신규 검사는 계정 등록 과정을 생략한 독립 EntityComponent를 사용하므로
HA 2026.9.4의 기기 등록 관련 경고가 나올 수 있어요. 운영 등록 경로의
변경이나 오류를 의미하지 않아요. 실제 HA 재시작 후 장시간 관찰은
운영 적용 뒤에 진행해야 해요.

검증 기준은 현재 운영 HA 2026.9.4의 Python 3.14·라이브러리 환경이에요.
최소 지원 HA 버전 전체 조합과 실제 기기 명령 전송은 이번 검증에 포함하지 않았어요.
테스트의 전송 경계는 실제 네트워크 대신 실패 전용 객체로 막았어요.

## 운영 적용 준비

아직 운영에 적용하지 않았어요. 사용자 승인 후 다음 순서로 적용해요.

1. 운영의 `climate.py`, `select.py`, `local_read_owner.py` 해시가 검토 당시와
   같은지 다시 확인하고 원본을 백업해요. 달라졌으면 덮어쓰지 않고 다시 비교해요.
2. HA를 중지한 상태에서 세 파일을 함께 교체하고 한 번 시작해요.
   Python 코드 변경이므로 설정 엔트리 재로드만으로 적용 완료를 판단하지 않아요.
3. 네 방의 기존 엔티티 ID, 가용성, 온도·모드와 자동 쾌적 값을 확인하고
   실제 수집 묶음 교체 때 비가용이 재발하는지 관찰해요.
4. 문제가 있으면 세 파일을 함께 복원하고 다시 시작해요.

센서·통계 이력, 자동화, 대시보드와 LG Local 발행기 배포는 변경 대상이 아니에요.
