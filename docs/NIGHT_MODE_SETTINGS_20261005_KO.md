# 냉장고 야간 설정 — 0.12.4

- 양문이 `2REFO1DBN3K_U`, 오김냉 `3REK2G03VI230D_2`에 방식 선택과 시작·종료 시각을 추가한다.
- 기존 밝기와 동일한 ThinQ 서버 저장 경로다. **로컬 단독 기능이 아니다.** 엔티티에 `value_source=thinq-server`, `local_appliance_control=false`를 표시한다.
- DB의 `app_settings` 6행을 `scripts/install_app_settings.py --database ... --apply`로 등록한다. 기존 행의 활성화·삭제 플래그와 라벨을 덮어쓰지 않는다.
- 방식은 꺼짐·일출/일몰·사용자 지정이다. 시각 엔티티는 사용자 지정일 때만 사용하며, 한국 현지 시각의 시·분을 받는다. 다른 방식에서 사용자 지정으로 전환할 때 Web 기본값 21:00–06:00을 쓴다.
- 하나의 설정만 바꾸고 밝기 및 나머지 시각을 보존한다. 설정을 새로 읽은 뒤 한 번만 SAVE하고, 새 GET의 전체 저장값으로 완료를 판단한다. 실패한 PUT을 자동 재전송하지 않는다.
- 밝기·일정은 기존 기기별 명령 잠금과 I/O 잠금을 공유한다. 기존 밝기 엔티티 ID·기록은 변경하지 않는다.
- Web에서 두 기기 각각 시작 시각 변경·복구, OFF 변경·복구를 확인했다. 배포 후 HA에서도 두 기기 각각 시작 21:00→21:01→21:00, 종료 06:00→06:02→06:00 및 OFF/사용자 지정/일출·일몰을 확인했다. 양문이 일출·일몰/40%, 오김냉 사용자 지정 21:00–06:00/30%로 원복했다.
- 관련 66개 테스트, 전체 809개 테스트 통과(환경에 따른 건너뜀 4개). 전체 테스트의 기존 AC router 대역에 빠졌던 조건 구독 메서드를 추가하고 구독 해제도 검사했다. 운영 AC 제어 코드는 바꾸지 않았다.
- 자체 코드 검토: 서버 경로 한정, 신규 범용 HTTP 우회 없음, 읽기/쓰기 모델 동일, 미확인 값을 낙관적으로 표시하지 않음, 시각 초 단위 거부, 엔티티 구독 수명주기 확인. 독립 에이전트 리뷰는 수행하지 않았다.
- 새 Python 어댑터가 포함되므로 최초 0.12.4 설치에는 코드 재로딩이 필요하다. 이후 이 6행의 DB 활성/비활성·삭제 플래그·라벨은 기존 hot reload로 반영된다.
- 0.12.4 Git 릴리스→HACS 설치→HA 재시작 1회로 적용했다. 운영 통합 113파일은 릴리스 코드와 일치한다. 설정 6개 생성 및 모드별 시각 입력의 활성/비활성 확인. 기존 18대 로컬 DB/HA 대응 점검 결과는 배포 전과 같았고 새 누락은 없었다.
